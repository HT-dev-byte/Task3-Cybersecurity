# Burp Suite Advanced — Intruder Fuzzing

## 1. Objective and Methodology

### Objective

The objective was to demonstrate the use of **Burp Suite's Intruder tool** to perform basic fuzzing against a web application's request parameter. Fuzzing involves sending a range of unexpected or specially crafted inputs and analyzing the application's responses for unusual behavior that may indicate a security weakness.

### Methodology

A login request was captured using **Burp Suite Proxy** and forwarded to **Intruder**. A suitable attack position was selected within the request, and the **Sniper** attack type was used to test one parameter at a time.

A small set of test inputs was then supplied to the selected parameter. The inputs included characters and strings commonly associated with injection and input-validation testing.

The responses were compared against the application's normal response to identify differences in status codes, response lengths, or other observable behavior.

## 2. Payloads Used for Fuzzing

The test payloads included a combination of special characters and common security-testing strings, such as:

```text
'
"
admin'--
<script>alert(1)</script>
!
```

These inputs were selected to test how the application handles unexpected characters and commonly encountered injection patterns.

## 3. Analysis of Fuzzing Results

The responses returned by the application were compared with the baseline response generated by a normal request.

Particular attention was given to:

* HTTP status codes
* Response length
* Error messages
* Changes in application behavior
* Whether supplied input was reflected in the response
* Unexpected differences between requests

Any significant deviation from the baseline can indicate that the tested input is being handled differently by the application and may warrant further manual investigation.

For example, a server error following a specially crafted character may indicate inadequate input handling, while reflected input may indicate a potential cross-site scripting issue. However, these observations alone do not necessarily confirm a vulnerability and should be followed by manual testing.

## 4. Conclusion

Burp Suite Intruder provides an efficient method for testing how a web application responds to a variety of unexpected inputs. By automating the delivery of test payloads and allowing responses to be compared against a baseline, Intruder can help identify parameters that require further security investigation.

The exercise demonstrated the use of **Proxy for request interception** and **Intruder for automated parameter testing**, providing a practical introduction to web application fuzzing and vulnerability identification.
